# 隐私与合规提示（公开仓库必读）

本仓库为 **Public**。它同时面向两类读者：人类访问者，以及会抓取 RAW 内容的各类 AI 服务。请按「内容会被永久保存、可被任意复制」的标准来写。

---

## 一、明确不要写入的内容

| 类别 | 具体项 |
| --- | --- |
| 身份与联络 | 手机号、私人邮箱、家庭住址、证件号、生日、社交账号 |
| 凭据 | 密码、API Key、Token、.env 内容、私钥、Cookie |
| 雇主信息 | 内部流程细节、未公开项目名、客户名称、经营数据、组织架构 |
| 第三方信息 | 同事 / 家人 / 客户的姓名、身份、可识别特征 |
| 法律敏感 | 健康记录、财务账号、合同原文、涉密或受监管数据 |

> 需要记录上述内容时，另建**私有仓库**，公开仓库只保留可公开版本；两者不要互相引用具体内容。

## 二、Git 的特殊风险

- **删除不等于消失**：`git rm` 只删除当前版本，历史提交、tag、fork、PR diff、GitHub 缓存中仍可能留存。
- **RAW 地址是公开的**：`raw.githubusercontent.com` 无需登录即可读取，任何拿到链接的人都能取到全文。
- **第三方 AI 服务**：把档案交给某个 AI 客户端，意味着内容按该服务的数据使用与留存政策处理；请自行确认其条款，尤其是企业账号与私有部署的区别。
- **自动化抓取**：公开仓库可能被搜索引擎、数据集、爬虫收录，事后难以完全撤回。

## 三、每次提交前的检查清单

- [ ] 本次新增内容是否愿意被陌生人、被雇主、被 AI 服务读到？
- [ ] 是否包含任何账号、密钥、内部项目名、他人身份信息？
- [ ] 是否引用了某个私有仓库或内部文档的具体内容？
- [ ] `git diff --cached` 是否已逐行看过（而不只是 `git add .`）？
- [ ] 临时文件、`.env`、导出的对话记录是否被 `.gitignore` 排除？

## 四、示例条目的处理

`README.md` 当前六章节均为**泛化占位示例**，不含任何真实个人信息，用于示范条目粒度。填充真实内容时：

1. 优先写**偏好与方法**（如「喜欢结构化输出」），少写**可识别事实**（如具体单位、住址、联系方式）。
2. 项目成果写可公开的量化结果，去掉客户与内部代号。
3. 拿不准的条目先开一个带 `area/privacy` 标签的 Issue 暂存判断，不要直接写进 README。

## 五、误提交处置

见 [`版本管理约定.md`](版本管理约定.md) 第六节：**先轮换凭据，再清理历史，最后记录结论**。
